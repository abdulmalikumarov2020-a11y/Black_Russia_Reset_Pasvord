## App Router — что важно понимать

App Router в Next.js по умолчанию рендерит компоненты на сервере.
Это значит, что обращение к файловой системе, базам данных и другим
серверным ресурсам можно делать прямо внутри компонента страницы.

### 1. `generateStaticParams`

Для динамических маршрутов, например `/posts/[slug]`, можно заранее
сообщить Next.js, какие страницы нужно собрать статически:

```ts
export async function generateStaticParams() {
  return getAllSlugs().map((slug) => ({ slug }))
}
```

### 2. `generateMetadata`

Для SEO каждой странице поста можно сгенерировать собственные мета-теги:

```ts
export async function generateMetadata({ params }: { params: { slug: string } }) {
  const post = getPostBySlug(params.slug)
  return {
    title: post?.title,
    description: post?.excerpt,
  }
}
```

### 3. Серверные и клиентские компоненты

Директива `'use client'` нужна только там, где требуется интерактивность —
например, в переключателе темы или поисковой строке. Всё остальное лучше
оставлять серверными компонентами: это уменьшает размер JS-бандла.

### 4. Инкрементальная сборка

Даже с большим количеством постов сборка остаётся быстрой благодаря
статической генерации: HTML собирается один раз на этапе `next build`.

### 5. MDX как источник контента

Хранить посты в `.mdx` удобно — они версионируются в Git, а Markdown
легко читать и редактировать без базы данных.

Удачной разработки!
